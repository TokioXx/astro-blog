#### 5. [TIL：不用 curl，靠 Bash 的 /dev/tcp 也能发 HTTP 请求](https://mareksuppa.com/til/bash-dev-tcp-http-without-curl/)
- **Source**: Hacker News | **Time**: 7 小时前 | **Heat**: 🔥 228
- **Links**: [Discussion · 128 条评论](https://news.ycombinator.com/item?id=48558018)
- **Summary**: 作者需要在一个被极度精简、连 curl/wget 都没有的容器里，验证它能否通过内部 Docker 网络访问另一服务的 /health 接口。解法是：bash 本身就能讲 HTTP。用 `exec 3<>/dev/tcp/service/8642` 打开 TCP 套接字，再 `printf` 手写一个带 `Host` 和 `Connection: close` 的 HTTP 请求写入文件描述符 3，最后 `cat <&3` 读回完整响应（状态行、头、空行、正文）。加 Authorization 头也只需多写一行。关键点：`/dev/tcp` 并非真实设备文件，磁盘上根本不存在，而是 bash 内部处理的重定向，由 bash 替你做 DNS 解析和 connect(2)。当然这不是真正的 HTTP 客户端——不处理重定向、分块、压缩、TLS，仅作连通性调试的应急手段。
- **Deep Dive**: 💡 **Insight**: 在最小化镜像盛行的今天，这类"用 shell 内建能力兜底"的技巧能在没有调试工具时救命；也提醒安全团队：精简容器并不等于无法发起网络请求。
